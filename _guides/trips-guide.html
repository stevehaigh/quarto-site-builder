Writing a Trip Page

Trip pages are ordinary Quarto pages with two extra shortcodes for plan entries. You write the prose; the shortcodes handle the icons, the map links and the legs between stops.

start a trip write the plan publish stop travel types when it's wrong where things live
01

Start a trip

# from the repo root
bin/new-trip.sh dolomites-2027 "Dolomites 2027"

That creates trips/dolomites-2027/index.qmd with the frontmatter filled in and a cheat sheet in a comment.

Set date: to the start of the trip before you publish. It orders the trips list and decides whether the trip files under Upcoming or Past — and it moves between the two on its own as the date passes.

02

Write the plan

Days are ## headings. Everything else is normal prose — drop the shortcodes wherever you want them.

## Sat 14 May — into the Dolomites

Easy first day, arrive by train from Verona.

{{< stop train "Verona Porta Nuova → Bolzano" time="08:12" booking="9K22H" >}}

{{< travel train "1 h 35" >}}

{{< stop hotel "Hotel Greif, Bolzano" nights=2 booking="BK-83321" >}}

Anything on the Piazza Walther works for dinner:

{{< travel walk "8 min" >}}

{{< stop eat "Vögele, Bolzano" note="trad. Tyrolean, book ahead" >}}
renders as
🚆Verona Porta Nuova → Bolzano08:12 · 9K22H
🚆1 h 35
🏨Hotel Greif, Bolzano2 nights · BK-83321
🥾8 min
🍽️Vögele, Bolzanotrad. Tyrolean, book ahead

Every place name and every leg is a live link — the place to a Google Maps search, the leg to Maps directions.

03

Preview and publish

quarto preview

Push to main and it's live. There's no draft step for trips — a plan is most useful while you're still making it, so the page goes up from day one and you keep editing it. (blog/drafts and hidden are still excluded from the production build; trips is not.)

stop — one entry in the plan

{{< stop TYPE "PLACE" >}}

Write the place name the way you'd type it into Google Maps — that's exactly where it gets linked.

Optional details

AttributeExampleNotes
timetime="09:40"—
nightsnights=2Pluralised for you
bookingbooking="BK-83321"—
costcost="€240"—
notenote="book ahead"Italic, on its own line
urlurl="https://…"Links the place here instead of Maps

time, nights, booking and cost render as one dot-separated line under the place, in that order — whichever of them you supply.

travel — a leg between two stops

{{< travel MODE "DURATION" >}}
🚗drive 🥾walk 🚴ride 🚆train ⛴️ferry ✈️flight

Put it between two stops. The origin and destination come from the stops either side, so you never type a place twice.

You type the duration yourself, copied from Google Maps while you're planning. That's deliberate: no API key, no billing, no build-time network calls, and nothing that silently goes stale in a way the page can't show you.

A leg with no stop after it renders nothing, so a trailing travel while you're mid-edit is harmless.

The thirteen stop types

Core
🏨hotel 🍽️eat ⛴️ferry 🚗drive ✈️flight 🚆train 👁️see
Activity
🚴ride 🥾walk 🍷wine
Admin
📝note ☐todo 💷cost

Admin entries are for things that aren't places — a parking reminder, a booking deadline, a running total. They get no map link, and they don't interrupt a leg, so a note sitting between two stops won't be mistaken for the leg's destination.

{{< stop todo "Book Vögele by 1 Apr" >}}
{{< stop cost "£1,480 all in" >}}

When something's wrong

The build warns rather than fails, and always renders something. Warnings appear in the quarto render output, prefixed [trips].

What you wroteWhat happens
Unknown stop typeGeneric • marker
Unknown travel modeRouted as driving
travel before any stopSkipped — nowhere to route from
stop missing type or placeSkipped

Adding a stop type

Add the icon to ICONS in _extensions/trips/trips.lua. If it isn't a place, add it to ADMIN too. A new travel mode also needs a TRAVEL_MODES entry mapping to a Google Maps travel mode — driving, walking, bicycling or transit.
